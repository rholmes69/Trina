A bundle is **conformant** with OKF v0.1 if all three conditions are met:

1. Every non-reserved `.md` file in the tree contains a parseable YAML frontmatter block.
2. Every frontmatter block contains a non-empty `type` field.
3. Every reserved filename (`index.md`, `log.md`) follows the structure described in [reserved-files](reserved-files.md) when present.

## Permissive Consumption

Consumers SHOULD treat all other constraints as soft guidance. Consumers MUST NOT reject a bundle because of:

| Condition | Reason |
|-----------|--------|
| Missing optional frontmatter fields (`title`, `description`, etc.) | These are recommended, not required. |
| Unknown `type` values | Types are not centrally registered. |
| Unknown additional frontmatter keys | Producers may extend freely. |
| Broken cross-links | May represent not-yet-written knowledge. |
| Missing `index.md` files | Index files are optional at every level. |

## Why Permissive?

OKF is meant to remain useful as bundles grow, get refactored, and are partially generated by agents. A strict validator would break real-world bundles that are in-flight or evolving. Permissive consumption is the correct default.
